# 电子挚友前端设计原则

## 1. 设计目标

电子挚友的界面目标是“私人、轻、可长期阅读”。它不是办公后台，也不是功能展示页。移动端 PWA 是默认体验，因此常驻顶部栏、底部输入区、卡片标题和正文都必须节制，给对话与人物内容留下空间。

设计优先级：

1. 聊天内容优先于导航说明。
2. 当前页面标题优先于辅助状态。
3. 用户可操作内容优先于解释性文案。
4. 说明文字只在必要时出现，避免把私人空间做成产品手册。

## 2. 全局文字层级

| 层级 | 用途 | 桌面字号 | 手机字号 | 颜色 | 使用原则 |
| --- | --- | ---: | ---: | --- | --- |
| 页面标题 | 顶部吸顶栏标题，如“石头”“石头的档案”“设置” | 24px | 17px | `--ink` | 只标识当前位置，不承担解释功能。 |
| 模块标题 | 内容型大模块名称，如“石头的小本本” | 24px | 18px | `--ink` | 用于内容分组和扫视，应突出但不压过页面标题。 |
| 卡片标题 | 档案卡标题、记忆详情标题、设置项标题 | 18px | 16px | `--ink` | 用于具体内容块；设置页的“当前模型”“数据控制”属于这一层，必须小于页面标题。 |
| 正文 | 说明、档案描述、设置说明 | 16px | 13px | `--muted` 或 `--ink` | 以可读为主，不做大段强调。 |
| 聊天正文 | 用户消息、石头消息、输入框文本 | 16px | 14px | 用户气泡 `--user-ink`，石头气泡 `--ink` | 聊天页的核心文本，手机端保持紧凑但清楚。 |
| 辅助信息 | 计数、筛选标签、状态提示 | 12px | 12px | `--muted` | 只帮助理解状态，不抢主内容。 |
| 微型标签 | 徽标、计数、菜单补充信息 | 11px | 10-11px | `--muted` 或状态色 | 只用于短标签，不承载长句。 |

## 3. 页面结构与文案策略

### 3.1 聊天页

结构：

1. 顶部吸顶栏：当前会话标题。
2. 消息流：用户消息、石头消息、等待/失败状态。
3. 底部输入区：文本输入框、发送按钮。

应突出的文案：

- 当前聊天标题：用于确认正在聊哪段，但长标题必须单行省略。
- 消息正文：聊天页的第一主角。
- 失败状态：需要能被看见，但不应像系统警告弹窗。

应简化的文案：

- 顶部栏不放副标题。
- 输入区只保留 placeholder，不增加使用说明。
- PWA、安装、缓存等说明不进入聊天页。

字体与颜色：

- 页面标题使用 `--text-page-title` 和 `--ink`。
- 聊天正文使用 `--text-chat`。
- 用户气泡使用 `--user` / `--user-ink`。
- 石头气泡使用白色背景和 `--ink`，头像负责角色识别。

### 3.2 石头档案页

结构：

1. 顶部吸顶栏：页面标题“石头的档案”。
2. 石头摘要：头像、姓名、轻量标签、短句。
3. 人设卡片：他是谁、说话方式、他对我的态度。
4. 记忆区：石头的小本本、筛选、记忆列表、详情抽屉。

应突出的文案：

- “石头”：人物识别，是档案页最强信息。
- “石头的小本本”：记忆管理入口，需要比普通卡片标题更突出。
- 记忆标题：帮助用户快速判断这条记忆是什么。

应简化的文案：

- 人设卡片不展示长副标题，手机端只保留标题和短正文。
- 记忆筛选使用短词：“类型”“状态”。
- 记忆状态只展示“正使用 / 待观察 / 已停用”。

字体与颜色：

- 顶部标题使用页面标题层级。
- “石头”人物名可大于普通模块标题，但只在档案摘要内使用。
- 记忆标题使用正文偏强或卡片标题层级，记忆内容用辅助正文。
- 状态色只用于记忆状态边缘、标签和危险操作，不铺满页面。

### 3.3 设置页

结构：

1. 顶部吸顶栏：页面标题“设置”。
2. 当前模型：状态点、模型选择、保存。
3. 数据控制：格式提示、对话导出、记忆导出、清空记忆。

应突出的文案：

- 顶部“设置”：设置页最高层级标题。
- “当前模型”“数据控制”：设置项标题，低于顶部标题。
- “对话导出”“记忆导出”“清空记忆”：列表行主文案，明确用户可以做什么。

应简化或删除的文案：

- “手机浏览器可添加到主屏幕”这类浏览器提示默认不展示。
- 数据控制列表下的二级说明如“历史聊天和会话摘要”“石头的小本本”不展示。
- 导出格式只保留“JSON”，不写迁移、备份等解释句。
- 不在设置页重复解释 PWA 安装，除非用户触发相关操作。

字体与颜色：

- 设置项标题使用卡片标题层级，必须小于顶部页面标题。
- “JSON”和临时状态使用辅助说明层级和 `--muted`，保持安静。
- 数据控制使用列表行和右侧箭头，不使用大按钮组；危险行只用文字色表达风险。

### 3.4 私人连接离线页

当 Windows 私人主机未开启、Tailscale 尚未连接或请求超时时，PWA 必须进入独立离线页，而不是继续展示一个无法回复的聊天壳。

结构与文案：

1. 状态标题：“石头还没开”。
2. 简短说明：提示用户先打开电脑桌面的“石头开关”，等待显示在线。
3. 唯一主操作：“再试一次”。

实现与视觉原则：

- 保持现有暖色背景、卡片圆角和角色语气，不显示浏览器、缓存、service worker 等技术术语。
- 离线状态不展示聊天记录、输入框或发送按钮，避免造成“可以输入但石头不会回复”的误解。
- 网络探测应有明确超时；当前实现最长等待约 3.5 秒后回退到 `offline.html`。
- 离线页只解释恢复使用所需的最短动作，不承担安装或网络诊断教程。

## 4. 颜色原则

| 变量 | 用途 | 原则 |
| --- | --- | --- |
| `--bg` | 页面背景 | 保持私人空间的暖色底，不做强对比。 |
| `--surface` / `--surface-strong` | 页面与卡片底色 | 用于分层，不制造厚重后台感。 |
| `--ink` | 主文字 | 页面标题、正文重点、可操作文字。 |
| `--muted` | 辅助文字 | 说明、计数、状态，不抢主内容。 |
| `--user` / `--user-ink` | 用户消息 | 只用于聊天气泡和少量主要状态。 |
| `--accent` / `--accent-ink` | 强操作与选中态 | 用于当前会话、主操作、焦点反馈。 |
| `--danger` | 危险操作 | 只用于删除、清空等不可逆操作。 |

## 5. 字号一致性落地规则

1. 新增页面标题必须使用 `--text-page-title`。
2. 新增模块标题必须使用 `--text-section-title`。
3. 新增卡片标题必须使用 `--text-card-title`。
4. 新增正文必须使用 `--text-body`，聊天消息使用 `--text-chat`。
5. 说明、状态、计数使用 `--text-caption` 或 `--text-micro`。
6. 手机端优先减少解释文字，而不是继续压缩到难读字号。
7. 同一页面内不新增一次性字号，除非是人物名或明确的视觉锚点。

## 6. 当前实现约束

- 设计变量维护在 `apps/web/styles.css` 的 `:root` 和手机端 media query 中。
- 私人连接离线状态由 `apps/web/offline.html` 与 `apps/web/sw.js` 共同提供。
- 手机端顶部吸顶栏保持紧凑，目标高度为 `46px + safe-area-inset-top`。
- 手机端聊天输入区保持紧凑，目标是单行输入时不明显挤占消息流。
- 手机端侧边栏里的入口只要会切回聊天页或聚焦输入框，都必须先收起侧边栏；包括新聊、历史对话和页面导航。
- 不通过新增依赖实现视觉系统；优先使用 CSS 变量和现有结构。
