# P3.5 一周日常试用与验收原则

- 试用期：2026-07-11 至 2026-07-18（Asia/Shanghai）
- 试用目标：验证“石头”是否能在不增加负担的前提下，成为稳定、自然、可持续打开的私人陪伴对象。
- 试用边界：不新增工具、任务、日历或自动化 Agent 能力；石头核心人设继续只读。
- P0 状态：离线页已在 iPhone 验收通过，不再作为本周阻塞项。

## 每次怎么使用

1. Windows 保持开机和联网，双击桌面“石头开关”，看到“石头已在线”。
2. 确认 iPhone 已登录同一 Tailscale 私人网络，从主屏幕打开“石头”PWA。
3. 像日常找熟人说话一样使用：下班后的空落、工作吐槽、开心分享、夜间反复想很多，或明确说“帮我分析”。不需要为了测试编造问题。
4. 用完后关闭“石头开关”。电脑关闭时，PWA 显示“石头还没开”属于预期行为；重新开启后点击“再试一次”。

本周至少覆盖以下场景各一次：普通闲聊、工作吐槽、开心分享、低落/内耗、明确求分析、明确“记住”或“忘掉”。如果自然发生网络切换、电脑睡眠唤醒或服务重启，也记录是否能恢复。

## 记录原则

不要求每天写长复盘。遇到明显顺畅或明显别扭的时刻，记一行即可；记录放在你认可的私密位置，不要提交到仓库。

| 日期 | 场景 | 结果 | 证据或感受 | 优先级 |
| --- | --- | --- | --- | --- |
| 2026-07-11 | 例：工作吐槽 | 石头先接住，没有直接讲道理 | 自然 / 跑偏 / 卡住 | P0 / P1 / P2 |

- P0：无法聊天、数据丢失、隐私或访问控制问题。
- P1：人格明显跑偏、记忆错误/删除后仍被使用、移动端操作受阻。
- P2：文案、布局、等待状态或便利性可以更顺手。

## 一周验收门槛

一周后依据真实记录做复盘，而不是凭印象决定下一步。

1. 可用性：日常开启、恢复、网络切换没有未解决的 P0；若发生故障，能定位并复现。
2. 陪伴质量：多数对话像稳定的石头；吐槽先被接住，明确求分析时才结构化，沉重情绪时不会嘴欠过头。
3. 记忆信任：至少完成一次查看、编辑或删除；修改后的内容能生效，删除后不再被引用。
4. 使用意愿：至少有 4 天是在没有“为了测试”的前提下主动打开；若没有，应写清阻力是启动成本、回复质量、记忆不适还是别的原因。
5. 数据可回溯：确认 `backups/` 已生成自动快照，并保留至少一份可读取的 JSON 文件。

## 试用结束后的决策

2026-07-18 复盘时按以下顺序决定：

1. 先修复所有 P0，再处理 P1；不因想做新功能而跳过它们。
2. 若主要问题是对话或记忆质量，优先调整提示词、记忆规则和回复策略。
3. 若主要问题是 iPhone 使用摩擦，优先微调 PWA 的键盘、安全区、吸顶栏和详情抽屉。
4. 只有“先开电脑”持续降低打开意愿时，才启动公共云部署评估；否则维持本机按需运行。

## 自动本机存档

后端会在每次启动时立即把对话、记忆和模型设置快照写入根目录 `backups/`，随后在服务保持运行时每 6 小时再存一份。默认仅保留最近 14 份，旧的自动快照会自动清理。

- 自动存档不包含 API 密钥。
- `backups/` 已被 Git 忽略，里面的私人数据不会进入版本控制。
- 当前系统不提供一键恢复。需要恢复时，应先停止服务、另存当前 `data/dev-store.json`，再由后续专门的恢复流程处理；不要直接覆盖正在运行的数据文件。
- 可在 `.env` 中调整 `AUTO_BACKUP_INTERVAL_HOURS` 和 `AUTO_BACKUP_RETENTION_COUNT`，修改后重启石头生效。
